# Arabic / English on the website

The whole website (landing, legal pages, sign-in, registration and every
shipper and carrier screen) works in Arabic (default, right-to-left) and
English (left-to-right). The AR | EN switch is in the platform's top bar, on
sign-in/registration and on the landing page; the choice is saved in the
browser (`localStorage['hemooltak-lang']`). The admin dashboard and the auth
emails stay Arabic.

## Where the words are

- Platform: `src/i18n/strings/*.js` — every text is `{ ar, en }` under a key.
  Components call `const { t } = useT(); t('trips.status')`.
  `{name}` in a text is filled from the params: `t('common.money', { amount })`.
- Landing and legal pages: `src/content/landing.js`, `src/content/legal.js`.
- **Never** write a text in a component. `npm run check:i18n` fails if a
  component holds Arabic, a key is missing, or a text has no English.

## Fixed values (translated by key, never by their Arabic)

| What | Where |
|---|---|
| Shipment / offer statuses, trip stages, account & document review | `strings/enums.js` |
| Quick messages (`messageKey`) | `strings/trips.js` → `quick` |
| Backend refusals (`details.reason`) | `strings/errors.js` → `reason` |
| Notifications (by `type`) | `strings/notifications.js` + `src/i18n/notifications.js` |
| Wallet transaction types and the backend's (English) descriptions | `strings/wallet.js`, `src/utils/transactions.js` |
| Cargo and truck types | admin-managed — see below |

## Cargo and truck types

Both lists are set by the admin (`config/cargoTypes`, `config/truckTypes`)
with an Arabic name and an English name (`nameEn`). In English the site shows
`nameEn`; if it is empty, the Arabic name. A truck type the admin never
renamed falls back to its built-in English name instead (it is the
translation of that same Arabic name). The field name is in one constant:
`ENGLISH_NAME_FIELD` in `src/i18n/catalog.js` (and the same in the admin
dashboard's `firebaseAdmin.js`).

## What is never translated

What users type (names, cities, notes, reasons, an admin's broadcast) is
shown exactly as written. In English such text is wrapped in Unicode
isolates so Arabic words keep their place in an English sentence.

## Notifications

The backend stores each notification already written in Arabic. In English
the text is rebuilt from its `type`, reading the values (amount, stage,
quick message) back out of the Arabic with the same template. Keep
`strings/notifications.js` word for word in step with the backend's
`functions/src/notificationText.ts`.

## Layout

`<html dir>` follows the language. Use logical CSS (`margin-inline-start`,
`text-align: start`, `inset-inline-end`) — never left/right — so a screen
works in both directions.
